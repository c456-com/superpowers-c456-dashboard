# 子项目② — 多视图 UX + 工作流首页 + 数据模型多视图

- 日期：2026-08-20
- 状态：草稿（待辉哥批准）
- 关联：superpowers-c456-dashboard（子项目①的展示层）

## 背景

子项目①锁定了 8 阶段工作流类型 + 数据模型目录。本子项目实现**展示形态**：
首页是「开发最佳实践工作流」，各类型有最佳视图，数据模型可多视图查看。

设计原则（结合行业最佳实践）：
- **首页 = 工作流总览**（宏观）：8 阶段卡片按流程串联，一眼看项目健康度
- **每个阶段用最合适的视图**（冲刺频繁看置顶、开发计划重时序、功能设计可图谱）
- **数据模型多视图**：从总览视觉（ER 图宏观）到蚂蚁视觉（字段级细节）切换

## 一、首页：开发最佳实践工作流

### 形态
首页不再罗列 6 个项目卡片，而是当前进入的项目呈现一条**工作流**：

```
[客户需求] → [调研] → [用户故事] → [产品设计] → [功能设计] → [路线图] → [开发计划] → [冲刺]
   (3篇)       (1篇)      (5篇)        (2篇)        (13篇)       (2篇)       (6篇)      (4篇)
```

- 每阶段一张卡片，按 `TYPE_ORDER` 横向串联（卡片间连线箭头表示流程流向）
- 卡片显示：阶段名 + 该阶段文档数 + 完成度（任务 checkbox 进度）
- 点卡片 → 进入该类型的文档列表/对应视图
- 空阶段（0 文档）用虚线卡/「缺少文档」提示引导创建

### 为什么（行业实践）
对应「需求→设计→开发」的经典交付流程（类似双菱/漏斗模型），让用户/客户
一眼看懂项目当前处于开发流程哪个阶段、每个阶段产出多少、哪里有缺口。

### 两种呈现（可切换）
- **工作流视图**（默认）：横向阶段卡 + 连线
- **列表视图**：紧凑的 8 类分组列表（现有手风琴的升级，带计数）

## 二、各阶段最佳视图

| 视图 | 归属 | 最佳实践形态 |
|------|------|-------------|
| **冲刺**（sprint） | 单项目内 | **置顶**+频繁看：冲刺卡墙（Kanban-like），当前冲刺置顶、状态清晰（进行中/计划/完成），checkbox 任务直显 |
| **开发计划**（plan） | 单项目内 | **重时序**：按时间先后顺序的卡片流（时间轴/card timeline），每计划卡标日期+任务进度 |
| **路线图**（roadmap） | 单项目内 | shadcn 最佳实践时间线（阶段标记 + desc + 时间） |
| **功能设计**（spec） | 单项目内 | **多视图切换**：默认按时间排序（列表/卡片）+ 可切**思维导图**看功能关联关系（图谱组件） |
| **客户需求/调研/用户故事/产品设计** | 单项目内 | 文档卡片列表（时间排序）|

### 功能设计图谱（思维导图）
- 需图谱/思维导图组件：功能节点 + 关联关系（`对应需求：`/`对应 Roadmap：` 元数据连线）
- 现有 MindmapView 已雏形，升级为真实图谱（节点可点开详情）

## 三、数据模型多视图（docs/models + dashboard）

目标：从「总览视觉」到「蚂蚁视觉」切换，看清所有信息。不做纯静态 md，让 dashboard 也能渲染。

### 视图分层（由宏观到微观）

| 层 | 视图 | 内容 | 对应文件/形态 |
|----|------|------|--------------|
| L1 总览 | **ER 图**（mermaid erDiagram） | 实体关系宏观 | `schema.md` 内嵌 erDiagram / `er.mmd` |
| L2 结构 | **字段表**（markdown table） | 每个实体的字段名/类型/说明 | schema.md 内 each 实体 table |
| L3 明细 | **JSON 契约** | 实际 `/data` 返回样例 | schema.md 附 JSON 样例 |
| L4 蚂蚁 | **类型/枚举明细** | 每字段取值枚举（如 doc.type 8 值）、判定规则 | schema.md 附录 / docs/models/types.md |
| L5 演进 | **变更记录** | 数据模型历史变更时间线 | changelog.md |

### dashboard 内实现
- 数据模型目录 `docs/models/` 本身是普通项目文档，被 scan 识别后
  通过 dashboard 文档视图可看（ER 图在 markdown 渲染中直接可见/可切换）
- 或在「设置」里加「数据模型」入口，直接渲染 schema.md（用现成的 markdown+ER 渲染能力）
